# [功能请求] 支持真正的多文件批量处理与多窗口状态同步

## 1. 批量执行（全自动）模式

### 问题背景
目前的软件界面仅支持用户通过向导式流程（提取音频 -> 识别 -> 翻译 -> 导出）单次处理一个媒体文件。用户强烈希望引入一个“全自动批量模式”的独立页面，允许一次性导入多个文件或文件夹，并让程序在后台无人值守地按队列自动完成所有文件的转录和翻译。

### 架构变更建议 (Main Process 主进程)
虽然前端可以勉强通过监听状态来模拟“自动点击下一步”，但真正的多文件并行或排队处理必须在 Node.js 后端建立可靠的任务队列，以防止阻塞 UI 线程和引发内存泄漏。

1. **任务队列系统 (Job Queue)**：在 `main` 进程中引入后台队列（例如使用 `better-sqlite3` 支持的持久化队列，或内存队列）来管理多个 `Job` 对象。
2. **IPC 接口扩展**：
   - `ipcMain.handle('add-batch-jobs', (event, filePaths) => ...)`：接收批量文件路径并入队。
   - `ipcMain.handle('start-batch-queue', (event) => ...)`：启动队列。
   - `ipcMain.handle('cancel-batch-queue', (event) => ...)`：中止队列。
3. **状态同步**：后端需要持续派发 `batch-progress` 事件，以便前端的“批量处理页面”实时渲染队列列表中各文件的进度条。
4. **错误隔离**：如果队列中的某个文件处理失败，后端应将其标记为 error，并自动开始处理下一个文件，而不是整个队列崩溃。

## 2. 设置界面原生多窗口与状态同步

### 问题背景
为了简化主工作区界面，我们需要将庞大的“设置 (Settings)”剥离出去。由于完全前端模拟的弹窗 (Modal) 无法满足操作系统的原生多窗口交互体验，我们需要将设置页面作为一个独立的系统级窗口 (Electron `BrowserWindow`) 弹出。

### 架构变更建议 (Main Process 主进程)
1. **多窗口入口**：在 Vite 配置中新增一个 `settings.html` 作为独立的渲染进程入口，并在主进程中管理 `settingsWindow` 的生命周期。
2. **状态同步 (State Sync)**：
   当前前端的 `SettingsViewModel` 仅在组件挂载时拉取一次设置。由于有两个独立窗口，如果用户在 `settingsWindow` 中修改了深色模式或界面语言，主进程必须主动向所有存活的窗口广播更新：
   `ipcMain.emit('settings-changed', newSettings)`
   这样 `mainWindow` 才能实现响应式更新，无需手动刷新应用。
3. **原生菜单绑定**：需要将操作系统的原生菜单（例如 macOS 下的 `Cmd+,` 首选项）绑定到唤起或聚焦 `settingsWindow` 的事件上。
